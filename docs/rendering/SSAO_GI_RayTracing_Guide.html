The short version

Global illumination (GI) is the light that reaches a surface after bouncing off other surfaces. The engine currently takes all such light from the HDR environment map, so a room lit by one window is still lit by the whole sky from every side. This guide adds GI with a grid of irradiance probes (the DDGI technique). Each probe stores how much light arrives at its position from every direction, and shaders blend the 8 probes around a pixel.

The probes are updated by shooting rays from them. The engine has no ray tracing yet, so the first version gets these rays by rendering a small cube map at each probe and reading it in the ray directions. Later the same rays are traced in hardware. Everything that happens after the rays (blending, multiple bounces, leak prevention, sampling) is written once and kept. That shared core is a ray buffer, one shading function for any point in the scene, a GPU material buffer, and a G-buffer that later rays can start from.

1. How to read this guide

Each phase chapter has the same parts: the goal, just enough theory, a data-flow diagram, what changes in this engine, code sketches, and a check that proves the phase works. The code is teaching code: correct and close to the engine's style, but names and details will change in the real implementation.

The phases are ordered by dependency: GI first (A–E), SSAO next (F), ray tracing last (G–H). Each phase ends with a renderer that builds and runs.

Conventions in the engine and in this guide
  • World space is Y-up and in meters. Light directions in the GPU structs point towards the light (DirectionalLight.Direction in Include/FrameSet.glslh).
  • The scene color target is linear HDR, RGBA16F. Tonemapping happens later, in ViewportComposite.glsl.
  • The environment irradiance cube u_EnvIrradianceTex stores irradiance already divided by π, so diffuse light is albedo * irradiance (see IBL() in Include/PBRCommon.glslh). The probes use the same convention, which allows an exact comparison in Phase C.
  • Only one frame is in flight (VulkanSwapChainH2M::Present waits for the frame's fence), so "history" resources from the previous frame need only one copy.

2.2 Where indirect light comes from now

The PBR fragment shader adds direct light (sun, point and spot lights, with shadows) and then calls IBL():

vec3 IBL(vec3 F0, vec3 Lr)
{
    vec3 irradiance = texture(u_EnvIrradianceTex, RotateVectorAboutY(u_EnvMapRotation, m_Params.Normal)).rgb;
    vec3 F  = fresnelSchlickRoughness(F0, m_Params.NdotV, m_Params.Roughness);
    vec3 kd = (1.0 - F) * (1.0 - m_Params.Metalness);
    vec3 diffuseIBL = m_Params.Albedo * irradiance;
    ...
    vec3 specularIrradiance = textureLod(u_EnvRadianceTex, ..., m_Params.Roughness * envRadianceTexLevels).rgb;
    vec2 specularBRDF = texture(u_BRDFLUTTexture, vec2(m_Params.NdotV, 1.0 - m_Params.Roughness)).rg;
    vec3 specularIBL = specularIrradiance * (F0 * specularBRDF.x + specularBRDF.y);
    return kd * diffuseIBL + specularIBL;
}

The irradiance cube depends only on the direction of the normal, never on the position. A floor under a table gets exactly the same sky light as a floor in the open. The only occlusion is the material's AO texture, which knows the mesh's own crevices but not other objects. SSAO and GI fix this:

  • SSAO darkens indirect light where nearby geometry blocks it (corners, contact areas). It works in screen space and is cheap.
  • GI replaces "sky light from all directions" with the light that actually arrives at the point, including light bounced off walls, with their color. It works in world space.
Existing code the new work builds on Compute pipelines exist (VulkanComputePipelineH2M for the environment map, and a hand-written compute pipeline in EnvMapVulkanShadowMapViewer). Point shadows already render a cube as 6 passes into a cube array (RecordLocalShadowPasses), which is what probe capture needs. EnvMapVulkanGlass and EnvMapVulkanWater show how a feature module owns its images, pipelines and descriptor sets. Shader includes work (Resources/Shaders/Include/*.glslh).

3. Theory primer

3.1 The rendering equation, in words

The light leaving a point x towards the eye is the light the point emits, plus all light arriving at x from every direction of the hemisphere above it, weighted by the material (the BRDF) and by the cosine of the angle to the normal:

Lo(x, ωo) = Le + ∫Ω f(ωi, ωo) Li(x, ωi) cos θi dωi

The incoming light Li is itself the outgoing light of some other point. That recursion is global illumination. Real-time renderers split the integral:

  • Direct light: the few directions that point at a light source. Evaluated exactly, with shadow maps for visibility. The engine already does this.
  • Indirect light: everything else. It is smooth on diffuse surfaces and is approximated: by the environment map today, by probes after this work.

3.2 Irradiance, and why diffuse light is cheap to store

For a diffuse (Lambertian) surface the BRDF is a constant, albedo/π, so it moves out of the integral. What remains, ∫ Li cos θ dω, is the irradiance E. It depends only on the position and the normal, and it is very smooth as a function of the normal, so an 8×8 octahedral map per probe is enough to store it.

Averaging the radiance of many rays with a cosine weight, Σ L cos θ / Σ cos θ, gives E/π. That is exactly the pre-divided convention of u_EnvIrradianceTex, so the probe result can replace the cube lookup without any extra factor.

3.3 Ambient occlusion

AO is the cosine-weighted fraction of the hemisphere above a point that is not blocked by nearby geometry. It is an approximation: it assumes blocked directions would have delivered as much light as open ones, and that blockers are black. It is still valuable because it captures small contact detail that probes, spaced a meter or more apart, cannot.

SSAO estimates AO from the depth buffer, so only what the camera sees can occlude. GTAO (Phase F) is a modern, physically based variant. With hardware ray tracing it becomes RTAO: short rays against the real scene.

3.4 Probes

A probe is a point in space that knows the irradiance arriving there from every direction. Probes form a regular 3D grid, the probe volume. To light a pixel, the shader finds the 8 probes of the grid cell that contains it, reads each probe's irradiance for the pixel's normal and blends them. The classic problem is leaking: a probe on the other side of a wall sees light the pixel doesn't. DDGI solves it by also storing, per probe and direction, the distance to the nearest surface, and ignoring a probe when the pixel is further from it than that surface (the Chebyshev test, Phase C).

3.5 Ray tracing in Vulkan, in one paragraph

The GPU builds a tree of bounding boxes over the triangles of each mesh (a bottom-level acceleration structure, BLAS) and one over all mesh instances of the scene (the top-level acceleration structure, TLAS). A shader can then ask "what does this ray hit first?" and gets the instance, triangle and barycentric coordinates. With ray queries (VK_KHR_ray_query) any shader can ask, including the compute shaders the engine already uses. The full ray tracing pipeline (VK_KHR_ray_tracing_pipeline) adds dedicated shader stages and is mostly needed for a path tracer.

4. The design rule: ray tracing replaces one step

A hybrid renderer keeps rasterization for what the camera sees directly and uses rays for the effects rasterization handles badly. GI gains the most from rays. The decisions below make sure the GI from Phases A–E keeps working, unchanged, when rays arrive in Phases G–H.

What the plan avoids

  • Voxel cone tracing and light propagation volumes. They need a voxelized copy of the scene, a separate data path that ray tracing makes obsolete.
  • Baked lightmaps. They need a second UV set per mesh, don't follow moving lights, and nothing of them carries over to ray tracing.
  • Screen-space GI as the main technique. It only knows what is on screen, so light from behind the camera vanishes when you turn around.
  • Convolving the capture cube directly into the irradiance map. It works, but ray tracing would make that code obsolete. Going through the ray buffer costs one small compute pass.

AG-buffer prepass and the direct/indirect split

Goal: per-pixel depth, normal, roughness and motion before the main lighting pass, and a PBR shader whose indirect light comes from replaceable functions. The picture must look exactly the same afterwards.

A.1 Why a prepass and not deferred shading

The engine is a forward renderer with many special paths (water, glass, skinned meshes, the water's reflection pass that reuses the mesh pipelines). Converting it to deferred shading would touch all of them. A depth + normal prepass (as in Doom 2016 and many forward+ renderers) gives SSAO, SSR and ray tracing what they need while the lighting stays forward. It even saves time: with the depth already written, the main pass uses depth test EQUAL and shades each pixel exactly once.

Share the depth attachment The prepass must write the same depth image the scene pass tests. Create the prepass framebuffer with the existing depth image of s_Framebuffer, and change the scene pass's depth load operation from clear to load. Keep CopySource = true on the scene target: water and glass still copy depth after the opaque meshes.

A.3 The prepass shaders

The prepass draws only opaque meshes, static and skinned (bones in set 2, as now). It uses the PBR vertex shader and a small fragment shader that samples the normal and roughness maps. Water and glass are not part of it.

// GBufferPrepass_Static.glsl (proposed), fragment stage
layout(location = 0) out vec4 o_NormalRoughness;
layout(location = 1) out vec2 o_Motion;

void main()
{
    vec3 N = GetShadingNormal();                // same code as the PBR shader: TBN * normal map
    float roughness = GetRoughness();           // map * value, clamped like the PBR shader does
    o_NormalRoughness = vec4(normalize(N), roughness);

    vec2 uvNow  = (v_ClipNow.xy  / v_ClipNow.w)  * 0.5 + 0.5;
    vec2 uvPrev = (v_ClipPrev.xy / v_ClipPrev.w) * 0.5 + 0.5;
    o_Motion = uvNow - uvPrev;
}
Depth EQUAL needs bit-identical positions The prepass and the scene pass must compute gl_Position with exactly the same instructions, or EQUAL fails on some pixels (speckles). Put the position code in one shared include and declare invariant gl_Position; in both shaders. If alpha-tested materials are ever added, the prepass must discard exactly like the scene pass.

A.4 Motion vectors

Motion is first needed in Phase F (temporal filtering), but the prepass is the natural place to write it. Each draw needs the previous frame's model matrix: keep it in the render data the renderer extracts from EnvMapVulkanScene each frame (a PreviousWorld next to the world matrix). The renderer keeps the camera's previous view-projection and adds it to the camera UBO in set 0. Skinned meshes would also need the previous bone matrices; a first version can use the current ones (a small error on fast animation).

// vertex stage, both prepass shaders
v_ClipNow  = u_ViewProjection         * u_Transform         * vec4(a_Position, 1.0);
v_ClipPrev = u_PreviousViewProjection * u_PreviousTransform * vec4(a_Position, 1.0);

A.5 Splitting direct and indirect light

Restructure IBL() in Include/PBRCommon.glslh into functions with one job each. Nothing changes visually; later phases only change the bodies.

vec3 IndirectDiffuse(vec3 P, vec3 N)       // irradiance / pi, same convention as u_EnvIrradianceTex
{
    return texture(u_EnvIrradianceTex, RotateVectorAboutY(u_EnvMapRotation, N)).rgb;   // Phase C: probes
}

vec3 IndirectSpecular(vec3 P, vec3 R, float roughness)
{
    int levels = textureQueryLevels(u_EnvRadianceTex);
    return textureLod(u_EnvRadianceTex, RotateVectorAboutY(u_EnvMapRotation, R), roughness * levels).rgb;   // Phase H: RT reflections
}

vec3 IndirectLight(vec3 F0, vec3 Lr, float ao)
{
    vec3 F  = fresnelSchlickRoughness(F0, m_Params.NdotV, m_Params.Roughness);
    vec3 kd = (1.0 - F) * (1.0 - m_Params.Metalness);
    vec2 brdf = texture(u_BRDFLUTTexture, vec2(m_Params.NdotV, 1.0 - m_Params.Roughness)).rg;
    vec3 diffuse  = m_Params.Albedo * IndirectDiffuse(m_Params.WorldPosition, m_Params.Normal);
    vec3 specular = IndirectSpecular(m_Params.WorldPosition, Lr, m_Params.Roughness) * (F0 * brdf.x + brdf.y);
    return (kd * diffuse) * ao + specular * SpecularOcclusion(ao);  // ao = 1 until Phase F
}

BOne surface-shading function and a GPU material buffer

Goal: one GLSL function that computes the light leaving any surface point, usable from a fragment shader now and from a ray-hit compute shader later, plus the material data it needs in a form that can be indexed.

B.1 What a probe ray needs to know

When a probe "looks" at a surface, it needs the light that surface sends back towards it. For GI only the diffuse part matters: probes store irradiance, which is smooth, and specular reflections depend on the viewer, so DDGI and similar systems shade ray hits as diffuse. The outgoing radiance of a hit point is:

L = emissive + (albedo / π) · (direct irradiance with shadows) + albedo · (probe irradiance at the hit)

The last term is the feedback that produces multiple bounces: each update adds the light the probes had last time.

// Include/ShadeSurface.glslh (proposed)
struct SurfacePoint
{
    vec3 Position;
    vec3 Normal;      // world space, facing the ray origin
    vec3 Albedo;
    float Metalness;  // metals have no diffuse: albedo * (1 - metalness)
    vec3 Emissive;    // already multiplied by the emissive intensity
};

vec3 ShadeSurfaceDiffuse(SurfacePoint s, vec3 toViewer, bool includeProbes)
{
    vec3 diffuseAlbedo = s.Albedo * (1.0 - s.Metalness);
    vec3 E = vec3(0.0);                                              // direct irradiance
    E += SunIrradiance(s.Position, s.Normal);                        // cascades, see B.2
    for (int i = 0; i < u_PointLightCount; i++) E += PointIrradiance(i, s.Position, s.Normal);  // with cube shadows
    for (int i = 0; i < u_SpotLightCount;  i++) E += SpotIrradiance(i,  s.Position, s.Normal);  // with spot shadows

    vec3 L = s.Emissive + diffuseAlbedo / PI * E;
    if (includeProbes)
        L += diffuseAlbedo * SampleProbeIrradiance(s.Position, s.Normal, toViewer);   // Phase C
    return L;
}

The light loops match PBRCommon.glslh (windowed inverse-square falloff, smooth spot cones), without the specular BRDF. Factor them so both the PBR shader and ShadeSurfaceDiffuse call the same falloff and shadow functions; never copy them.

B.2 Sun shadows away from the camera

The four cascades follow the camera, but a probe ray can hit a surface outside all of them (behind the camera, far away). Pick a rule and keep it: outside the last cascade, treat the point as lit. Optionally add a fifth, coarse, static cascade covering the whole probe volume, rendered only when the volume or the sun changes. With ray tracing (Phase H) the problem disappears: trace a shadow ray to the sun instead.

B.3 The GPU material buffer

Today each material lives in its own descriptor set and the shader knows which material it is drawing. A probe capture could keep that model, but a ray hit cannot. Add one storage buffer with all materials of the EnvMapVulkanMaterialLibrary:

// std430, one entry per material (proposed)
struct GPUMaterial
{
    vec4  AlbedoColor;        // rgb = color * average of the albedo map (see below)
    vec4  Emissive;           // rgb = emissive color * intensity
    float Metalness;
    float Roughness;
    uint  Flags;              // bit 0 = glass, bit 1 = double-sided, ...
    uint  AlbedoMapIndex;     // bindless index, Phase G (0xFFFFFFFF = none)
    uint  NormalMapIndex;
    uint  RoughnessMapIndex;
    uint  MetalnessMapIndex;
    uint  EmissiveMapIndex;
};
  • The library assigns each material a dense index. MeshPartComponent already references its material by ID, so the renderer maps ID → index when it extracts the draw list and passes the index as a push constant.
  • The library already keeps a content hash per material (used for the unsaved "*" marker). Re-upload an entry when its hash changes, and re-upload all entries after ResolveVariants.
  • The average-albedo trick. Probes are low-frequency, so the capture doesn't need texture detail. Compute each albedo map's average color once (read its smallest mip) and store color × average in AlbedoColor. The same trick lets the first ray-traced version run before bindless textures exist.
Check Add a temporary debug view in which the PBR shader returns ShadeSurfaceDiffuse (without probes) instead of its normal lighting, using the material buffer. Diffuse surfaces should look like a flatter version of the normal image: same lights and shadows, no reflections, no texture detail.

CThe probe volume: storage and sampling

Goal: a probe grid that is part of the scene, the textures that hold its data, and the shader code that lights pixels from it. The probes are first filled from the environment map, which gives an exact correctness test.

C.1 The ECS component

The probe volume is an entity like the water: selectable in the Scene Hierarchy, edited in Properties, moved and scaled with the gizmo, and saved in the .mscene file by EnvMapVulkanSceneSerializer.

// EnvMapVulkanComponents.h (proposed)
struct ProbeVolumeComponent
{
    glm::ivec3 ProbeCounts = { 8, 4, 8 };   // the volume's size comes from the TransformComponent scale
    bool  Enabled = true;
    int   RaysPerProbe = 192;
    float Hysteresis = 0.97f;               // how much of the old value each update keeps
    float NormalBias = 0.25f;               // fractions of the probe spacing
    float ViewBias = 0.25f;
    float BounceIntensity = 1.0f;
    int   ProbesPerFrame = 16;              // update budget (Phase D)
    bool  Relocation = true;                // Phase E
};

The probe at grid coordinate (i, j, k) sits at origin + (i, j, k) * spacing + offset[i, j, k], where origin is the volume's minimum corner, spacing = size / (counts - 1), and offset is zero until relocation (Phase E). Keep the volume axis-aligned at first (rotation locked, like the water's X and Z rotation); a rotated volume only needs the inverse rotation applied before the grid math.

C.2 The atlases

Each probe stores two small square maps of the sphere in the octahedral mapping (the sphere is projected onto an octahedron, which unfolds into a square with little distortion):

AtlasPer probeFormatContents
Irradiance8×8 + 1 texel border = 10×10RGBA16Firradiance/π for a normal pointing in the texel direction, stored encoded (C.4)
Visibility16×16 + 1 texel border = 18×18RG16Fmean distance and mean squared distance to the nearest surface in the texel direction
Probe data1 texelRGBA16Fxyz = relocation offset, w = state (active or inactive) (Phase E)

Probes are laid out as tiles: tile (i + j·countX, k) for probe (i, j, k), so the irradiance atlas is countX·countY·10 by countZ·10 texels. An 8×4×8 volume gives a 320×80 irradiance atlas (about 200 KB) and a 576×144 visibility atlas.

The one-texel border makes bilinear filtering work at tile edges. After every update, each border texel copies its neighbor across the octahedral seam: along an edge, the interior texel mirrored about the edge's midpoint; at a corner, the opposite interior corner.

vec2 SignNotZero(vec2 v) { return vec2(v.x >= 0.0 ? 1.0 : -1.0, v.y >= 0.0 ? 1.0 : -1.0); }

vec2 OctEncode(vec3 n)          // unit vector -> [-1, 1]^2
{
    n /= abs(n.x) + abs(n.y) + abs(n.z);
    vec2 p = n.xy;
    if (n.z < 0.0) p = (1.0 - abs(n.yx)) * SignNotZero(n.xy);
    return p;
}

vec3 OctDecode(vec2 p)          // [-1, 1]^2 -> unit vector
{
    vec3 n = vec3(p, 1.0 - abs(p.x) - abs(p.y));
    if (n.z < 0.0) n.xy = (1.0 - abs(n.yx)) * SignNotZero(n.xy);
    return normalize(n);
}

vec2 ProbeAtlasUV(ivec3 probe, vec3 dir, int interior, vec2 atlasSize)
{
    int tile = interior + 2;                                           // interior + border
    ivec2 tileCoord = ivec2(probe.x + probe.y * u_ProbeCounts.x, probe.z);
    vec2 inTile = (OctEncode(dir) * 0.5 + 0.5) * float(interior) + 1.0; // skip the border
    return (vec2(tileCoord * tile) + inTile) / atlasSize;
}

C.4 Sampling: the heart of DDGI

vec3 SampleProbeIrradiance(vec3 P, vec3 N, vec3 V)   // V: unit vector from P towards the viewer (or ray origin)
{
    vec3 biasedP = P + (N * u_NormalBias + V * u_ViewBias) * u_ProbeSpacing;
    ivec3 base  = clamp(ivec3(floor((biasedP - u_ProbeOrigin) / u_ProbeSpacing)), ivec3(0), u_ProbeCounts - 2);
    vec3 alpha  = clamp((biasedP - (u_ProbeOrigin + vec3(base) * u_ProbeSpacing)) / u_ProbeSpacing, 0.0, 1.0);

    vec3 sum = vec3(0.0); float weightSum = 0.0;
    for (int i = 0; i < 8; i++)
    {
        ivec3 offset = ivec3(i, i >> 1, i >> 2) & 1;
        ivec3 probe  = base + offset;
        if (!ProbeIsActive(probe)) continue;
        vec3 probePos = ProbePosition(probe);                 // grid position + relocation offset

        // 1. backface weight: a probe behind the surface counts less (smooth, never exactly 0)
        vec3 dirToProbe = normalize(probePos - P);
        float w = pow(max(0.0001, (dot(dirToProbe, N) + 1.0) * 0.5), 2.0) + 0.2;

        // 2. visibility (Chebyshev): is the point further from the probe than the probe's nearest surface?
        vec3 probeToPoint = biasedP - probePos;
        float d = length(probeToPoint);
        vec2 m = textureLod(u_ProbeVisibility, ProbeAtlasUV(probe, probeToPoint / d, 16, u_VisibilityAtlasSize), 0.0).rg;
        float chebyshev = 1.0;
        if (d > m.x)
        {
            float variance = abs(m.x * m.x - m.y);
            float delta = d - m.x;
            chebyshev = variance / (variance + delta * delta);
            chebyshev = chebyshev * chebyshev * chebyshev;      // sharpen
        }
        w *= max(0.05, chebyshev);

        // 3. crush tiny weights, then apply the trilinear weight
        const float crush = 0.2;
        if (w < crush) w *= w * w / (crush * crush);
        vec3 tri = mix(1.0 - alpha, alpha, vec3(offset));
        w *= tri.x * tri.y * tri.z;

        // 4. read the irradiance for the normal, blend in a perceptual space
        vec3 irr = textureLod(u_ProbeIrradiance, ProbeAtlasUV(probe, N, 8, u_IrradianceAtlasSize), 0.0).rgb;
        irr = pow(irr, vec3(u_IrradianceGamma * 0.5));         // stored as E^(1/gamma), gamma = 5
        sum += w * irr; weightSum += w;
    }
    if (weightSum <= 0.0) return EnvironmentIrradiance(N);  // fallback
    vec3 r = sum / weightSum;
    return r * r;                                           // back to linear
}

Why the encoding? Irradiance spans orders of magnitude. Blending in linear space lets one bright probe dominate and makes dark corners blotchy. DDGI stores E1/5, blends in the square-root space of the decoded value, and squares at the end.

Outside the volume, fade towards EnvironmentIrradiance(N) over the last half cell, so objects leaving the volume don't pop.

In IndirectDiffuse(): return u_ProbesEnabled ? SampleProbeIrradiance(P, N, normalize(u_CameraPosition - P)) : EnvironmentIrradiance(N);

C.5 Fill from the environment and visualize

Before any capture exists, a compute pass fills every irradiance texel with u_EnvIrradianceTex in the texel's direction (with the environment rotation), encoded, and every visibility texel with a large distance (1.5 × the spacing, for both moments). DUpdating the probes through a ray buffer

Goal: real GI. Each update gives every probe in the batch a fresh set of rays, and compute passes blend them into the atlases. This is where the image changes: colored bounce light, dark interiors, emissive meshes lighting their surroundings.

D.1 The ray buffer

An RGBA16F storage image, RaysPerProbe wide (e.g. 192), with one row per probe updated in this batch. Texel (r, p): rgb = radiance arriving at probe p along ray r, a = hit distance. Two special cases:

  • Miss (the ray reaches the sky): radiance = environment radiance in that direction, distance = a large value (e.g. 1e4).
  • Backface hit (the ray hits the inside of a mesh): the probe is probably inside geometry. Store distance = −0.2 × t. The blend ignores these rays for irradiance, and relocation (Phase E) counts them.

The ray directions are a spherical Fibonacci set (evenly spread points on a sphere), rotated by a new random rotation for every update, so successive updates sample different directions and the result converges instead of aliasing:

vec3 SphericalFibonacci(float i, float n)
{
    const float PHI = 1.61803398875;
    float phi = 2.0 * PI * fract(i * (PHI - 1.0));
    float cosTheta = 1.0 - (2.0 * i + 1.0) / n;
    float sinTheta = sqrt(clamp(1.0 - cosTheta * cosTheta, 0.0, 1.0));
    return vec3(cos(phi) * sinTheta, sin(phi) * sinTheta, cosTheta);
}
vec3 ProbeRayDirection(int ray) { return mat3(u_RandomRotation) * SphericalFibonacci(float(ray), float(u_RaysPerProbe)); }

D.2 Filling the ray buffer by rasterization

  1. Capture: for each probe of the batch, render a cube map at the probe position, 32×32 per face, into cube arrays (one cube per batch slot). Two color attachments, RGBA16F radiance and R32F signed distance, plus depth. This is the same 6-passes-per-cube pattern as the point shadows in RecordLocalShadowPasses, with a 90° perspective per face.
  2. The capture shader draws every opaque mesh (static and skinned) and the skybox. Its fragment stage builds a SurfacePoint from the material buffer, calls ShadeSurfaceDiffuse(s, toProbe, true), and writes the radiance and gl_FrontFacing ? dist : -0.2 * dist. Culling must be off, or backfaces are never seen. The skybox writes the environment radiance and the large distance.
  3. Resample (compute, one thread per ray): read the cube in the ray direction and write the ray buffer. This is the only step that knows about cubes.
// ProbeResample.glsl (proposed), compute
layout(local_size_x = 64) in;
void main()
{
    int ray = int(gl_GlobalInvocationID.x), slot = int(gl_GlobalInvocationID.y);
    if (ray >= u_RaysPerProbe) return;
    vec3 dir = ProbeRayDirection(ray);
    vec3 radiance = textureLod(u_CaptureRadiance, vec4(dir, float(slot)), 0.0).rgb;
    float dist    = textureLod(u_CaptureDistance, vec4(dir, float(slot)), 0.0).r;   // nearest filtering
    imageStore(u_RayBuffer, ivec2(ray, slot), vec4(radiance, dist));
}

D.4 Blending the rays into the atlases

One workgroup per probe, one thread per irradiance texel (8×8) or visibility texel (16×16). Each thread loops over all rays of its probe.

// ProbeBlendIrradiance.glsl (proposed), compute, local_size 8x8
void main()
{
    ivec3 probe = BatchProbe(int(gl_WorkGroupID.x));
    vec2 octUV  = ((vec2(gl_LocalInvocationID.xy) + 0.5) / 8.0) * 2.0 - 1.0;
    vec3 texelDir = OctDecode(octUV);

    vec3 sum = vec3(0.0); float weightSum = 0.0;
    for (int r = 0; r < u_RaysPerProbe; r++)
    {
        vec4 ray = imageLoad(u_RayBuffer, ivec2(r, int(gl_WorkGroupID.x)));
        if (ray.a < 0.0) continue;                         // backface: skip
        float w = max(0.0, dot(texelDir, ProbeRayDirection(r)));
        sum += ray.rgb * w; weightSum += w;
    }
    vec3 irradiance = weightSum > 0.0 ? sum / weightSum : vec3(0.0);   // = E / pi

    ivec2 texel = ProbeTileOrigin(probe, 10) + 1 + ivec2(gl_LocalInvocationID.xy);
    vec3 previous = pow(imageLoad(u_IrradianceAtlas, texel).rgb, vec3(u_IrradianceGamma));   // decode
    vec3 result = mix(irradiance, previous, u_Hysteresis);
    imageStore(u_IrradianceAtlas, texel, vec4(pow(result, vec3(1.0 / u_IrradianceGamma)), 1.0));
}

The visibility blend uses the same loop with two changes: the weight is sharpened, pow(max(0, dot(texelDir, rayDir)), 50.0), and it accumulates d and d² with d = min(abs(ray.a), maxRayDistance), where maxRayDistance is about 1.5 × the spacing. A third small pass then updates the border texels of both atlases (C.2).

Practical details that matter
  • Order and barriers: the capture samples the atlases (bounce light) while the blend writes them. Within a frame the capture runs first, so a single atlas works. Keep the order strict with pipeline barriers: capture attachments → resample read, ray buffer write → blend read, blend write → border read/write, border write → fragment-shader sampling (scene pass and the next update's capture).
  • Large changes: when a texel's irradiance changes a lot (a light switched on), lower its hysteresis, e.g. to 0.5 above a threshold, so lights respond quickly without flicker the rest of the time.
  • Energy: the feedback loop converges because each bounce is multiplied by albedo < 1. Clamp albedo in the material buffer to 0.9 and clamp very bright ray radiance before blending, or a strong emissive surface produces fireflies in the probes.
Cost and the update budget 32×32×6 = 6144 pixels per probe is little; the real cost is draw calls, since every mesh is drawn 6 times per probe. Cull meshes per face against the face frustum and a maximum ray distance. With 16 probes per frame and 30 meshes that is still up to about 2900 draws per frame, so start with 4–8 probes per frame and measure in the Rendering Stats panel. This is the cost ray tracing removes: 192 rays per probe need no draw calls.

D.5 Scheduling and invalidation

  • Round robin: update ProbesPerFrame probes per frame, cycling through the volume. Every probe is updated every count / budget frames.
  • Dirty first: the renderer already uses generation counters (for example, for shadow-map resolution changes). Keep a scene "lighting generation" that increases when a light, a model transform, a material or the environment changes, and mark the probes within reach of the change as dirty. Dirty probes go to the front of the queue.
  • Bake: a button that updates all probes for about 32 iterations, the first with hysteresis 0, the rest with the normal value. That gives a converged, multi-bounce result for static scenes. Baked probe data can be saved next to the scene later.

D.6 Water and glass

The capture leaves both out at first: glass counts as fully transparent and the water surface as absent. Underwater, the probes then see sky light through the water, and the existing WaterVolume.glslh absorption and caustics darken and color it, which is a reasonable first result. Later, add the water to the capture as an opaque, dark, blue-tinted surface, so probes below the surface receive less light.

ELight leaks, probe relocation and tuning

Goal: remove the typical probe artifacts. Most of this phase is tuning, but two features are needed: moving probes that lie inside geometry, and switching off probes that can't contribute. The relocation pass is part of Figure 7.

E.1 Probes inside walls

A regular grid ignores the scene, so some probes land inside walls or objects. Such a probe sees mostly backfaces, and the ray buffer already says so: count the rays with negative distance.

  • Relocation: if more than 25% of a probe's rays hit backfaces, move the probe a little beyond the closest backface, along that ray's direction. If its closest front-face hit is nearer than a minimum distance, move it away from that surface. Limit the offset to 45% of the spacing so the probe stays in its cell, and store it in the probe data image.
  • Classification: if a probe is still inside, or no surface lies within a cell's reach, mark it inactive. Sampling skips inactive probes (ProbeIsActive), and so does the scheduler, which saves time.
  • Relocation and classification run for a few iterations after the volume moves or the geometry changes, then stop.

E.2 Bias

The normal and view biases move the sample point off the surface before the visibility test. Too little causes dark blotches where a surface "occludes itself"; too much lets light leak through thin walls. Start with 0.2–0.3 of the spacing each. Document a rule for content: walls should be at least about a tenth of the probe spacing thick, and the spacing smaller than the rooms (1 m for interiors, 2–4 m outdoors).

E.3 Debug views

  • Probe spheres colored by state (active, inactive, relocated), with the offset drawn as a line.
  • "Probe irradiance only": albedo forced to white, so the GI can be judged without textures.
  • A visibility view that shows each probe's mean distance as its sphere color.

E.4 Specular occlusion from the probes

Reflections still come from the environment cube, so interiors reflect the bright sky (fixed for good in Phase H). A cheap improvement now: scale IndirectSpecular by the ratio of probe irradiance to environment irradiance in the reflection direction, clamped to [0, 1]. Dark rooms then get dark reflections. Reflection-probe systems use the same normalization idea.

FSSAO with GTAO and a reusable temporal filter

Goal: small-scale contact occlusion that probes can't provide, and a temporal filter that every later noisy effect (RTAO, ray-traced reflections) reuses.

F.1 GTAO in short

Ground Truth Ambient Occlusion (Jimenez et al., 2016) examines a few slices through the pixel, each a plane containing the view direction. In each slice it walks the depth buffer in both directions and finds the highest horizon angle the geometry reaches. The visible part of the hemisphere between the two horizons is integrated analytically, with the cosine weight, using the normal projected into the slice. The result is close to a ray-traced reference at a fraction of the cost.

// per pixel, view space: P = position, V = normalize(-P), N = normal (from the G-buffer)
float visibility = 0.0;
for (int s = 0; s < SLICES; s++)
{
    float phi = (float(s) + noise.x) * PI / float(SLICES);
    vec3 dir    = vec3(cos(phi), sin(phi), 0.0);
    vec3 ortho  = dir - dot(dir, V) * V;
    vec3 axis   = normalize(cross(ortho, V));
    vec3 projN  = N - axis * dot(N, axis);
    float projLen = length(projN);
    float n = sign(dot(ortho, projN)) * acos(clamp(dot(projN, V) / projLen, -1.0, 1.0));

    vec2 horizonCos = vec2(-1.0);                  // both sides
    for (int j = 0; j < STEPS; j++)                // marched in screen space over the radius
        for (int side = 0; side < 2; side++)
        {
            vec3 S = ViewPositionAt(uv + (side == 0 ? 1.0 : -1.0) * StepOffset(j, noise.y, dir.xy));
            vec3 d = S - P; float len = length(d);
            float c = dot(d / len, V);
            c = mix(-1.0, c, Falloff(len));          // samples beyond the radius fade out
            horizonCos[side] = max(horizonCos[side], c);
        }

    float h0 = n + max(-acos(horizonCos.y) - n, -PI * 0.5);
    float h1 = n + min( acos(horizonCos.x) - n,  PI * 0.5);
    float a0 = -cos(2.0 * h0 - n) + cos(n) + 2.0 * h0 * sin(n);
    float a1 = -cos(2.0 * h1 - n) + cos(n) + 2.0 * h1 * sin(n);
    visibility += projLen * 0.25 * (a0 + a1);
}
float ao = visibility / float(SLICES);

F.2 The passes

  1. Depth mips (compute): a small mip chain of linear view depth, so distant samples read coarser mips (cache-friendly).
  2. GTAO (compute, half resolution): 2 slices × 8 steps per pixel, with per-pixel noise (interleaved gradient noise, rotated every frame) so the temporal filter averages different samples.
  3. Spatial denoise: a 5×5 bilateral blur whose weights fall off with depth and normal differences, so it never blurs across edges.
  4. Temporal accumulation (F.3).
  5. Upsample to full resolution with depth-aware weights: prefer the half-res samples whose depth is closest to the full-res depth.

The result is one R8 image, the AO image interface from Phase A, bound in set 0 at binding 15 (u_AOImage). The PBR shader reads it at the pixel and passes it to IndirectLight(). The SSAO module (proposed EnvMapVulkanSSAO) owns a private compute set with the G-buffer images (sampled), the depth mips, the AO images (storage) and a small UBO (radius, intensity, falloff, frame index, projection parameters).

F.3 The temporal filter as a reusable tool

Write it as a small class (proposed EnvMapVulkanTemporalFilter) that takes a "current" image plus the G-buffer motion and depth, and owns a history image pair:

  • Reproject: prevUV = uv - motion; read the history there.
  • Reject on disocclusion: compare the depth stored with the history to the current depth, and drop the history if they differ by more than a few percent.
  • Clamp: limit the history to the min/max (or mean ± k·σ) of the current value's 3×3 neighborhood, which prevents ghosting when things move.
  • Blend: mix(current, history, 0.9), with a per-pixel sample count so freshly disoccluded pixels converge faster.

With one frame in flight, a ping-pong pair is all the history it needs. RTAO and the ray-traced reflections in Phase H use the same class.

F.4 Applying AO correctly

  • Indirect light only. Direct light already has shadows; darkening it with AO looks dirty.
  • Combine with the material AO: ao = min(ssao, materialAO), since both describe the same kind of occlusion.
  • Multi-bounce (Jimenez 2016): occluded areas on bright surfaces still receive light bounced inside the crevice. With a = 2.0404·albedo − 0.3324, b = −4.7951·albedo + 0.6417, c = 2.7552·albedo + 0.6903: aoColored = max(vec3(ao), ((ao·a + b)·ao + c)·ao).
  • Specular occlusion (Lagarde, Frostbite): clamp(pow(NdotV + ao, exp2(−16·roughness − 1)) − 1 + ao, 0, 1), which fills the SpecularOcclusion() slot of Phase A.
  • With GI on: the probes already handle large-scale occlusion, so use a smaller SSAO radius (about 0.5 m) to avoid darkening the same area twice.

A cube on a floor should get a soft dark contact line without a dark halo on the wall behind it (that would mean the bilateral filter is failing). GRay tracing foundation

Goal: the scene exists as acceleration structures, and a compute shader can trace a ray and learn everything about what it hit: position, normal, UV and material. The only visible change is a debug view.

G.1 Device setup

In the H2M Vulkan device creation (VulkanDeviceH2M), enable when the GPU supports them:

  • Extensions: VK_KHR_acceleration_structure, VK_KHR_ray_query, VK_KHR_deferred_host_operations (required by the acceleration structure extension), and later VK_KHR_ray_tracing_pipeline for the path tracer.
  • Features: bufferDeviceAddress, accelerationStructure, rayQuery, and from descriptor indexing runtimeDescriptorArray, descriptorBindingPartiallyBound, descriptorBindingVariableDescriptorCount, shaderSampledImageArrayNonUniformIndexing, descriptorBindingSampledImageUpdateAfterBind.
  • Keep a RayTracingSupported flag. Every ray-traced effect falls back to its raster version when it is false.

G.2 Buffers rays can read

Vertex and index buffers need VK_BUFFER_USAGE_SHADER_DEVICE_ADDRESS_BIT, VK_BUFFER_USAGE_ACCELERATION_STRUCTURE_BUILD_INPUT_READ_ONLY_BIT_KHR and VK_BUFFER_USAGE_STORAGE_BUFFER_BIT, and their memory must be allocated with the device-address flag (with VMA: VMA_ALLOCATOR_CREATE_BUFFER_DEVICE_ADDRESS_BIT on the allocator). That is a change in the H2M Vulkan vertex and index buffer classes. Shaders then read vertices through GL_EXT_buffer_reference.

G.3 Skinned meshes need compute skinning

Today skinning happens in the vertex shader (bones in set 2), so skinned vertices never exist in memory and can't go into an acceleration structure. Add a compute skinning pass that writes skinned vertices into a per-instance buffer every frame. The BLAS of a skinned instance is built once with ALLOW_UPDATE and refitted (a cheap update) every frame. The raster passes can later read the same buffer instead of skinning again.

G.4 BLAS and TLAS from the ECS

  • BLAS: one per model (MeshH2M), with one geometry per mesh part, built and compacted when the model loads. Part transforms (the Part Transform edits) go into the geometry's transform buffer.
  • TLAS: rebuilt every frame from the render data the renderer already extracts from EnvMapVulkanScene. One VkAccelerationStructureInstanceKHR per model instance: the 3×4 world transform (glm is column-major and the Vulkan matrix is row-major, so transpose), instanceCustomIndex = index into a GPU instance table, a mask (bit 0 opaque, bit 1 glass, bit 2 water), and VK_GEOMETRY_INSTANCE_TRIANGLE_FACING_CULL_DISABLE_BIT_KHR for double-sided materials.
  • Instance table (storage buffer): per instance, the vertex and index buffer addresses and the offset of its parts' material indices.
  • Barrier between the build and the first use: VK_PIPELINE_STAGE_ACCELERATION_STRUCTURE_BUILD_BIT_KHR → VK_PIPELINE_STAGE_COMPUTE_SHADER_BIT, access ACCELERATION_STRUCTURE_WRITE → ACCELERATION_STRUCTURE_READ.

G.5 Bindless textures

ResourceManager's texture cache already owns every 2D texture (keyed by path and sRGB). Give each cached texture a permanent slot in one large descriptor array (sampler2D u_Textures[], partially bound, update-after-bind). The material buffer's map index fields (Phase B) point into it. Raster shaders keep their per-material sets; only ray hits use the array.

G.6 Set 3 and shader reflection

The new set 3 holds the TLAS, the instance table, the material buffer and the bindless array. VulkanShaderH2M builds layouts by reflection, and it may not handle runtime arrays and acceleration structures. The safe route is the one EnvMapVulkanShadowMapViewer already takes: create this set's layout and the compute pipelines that use it by hand.

G.7 Tracing a ray from a compute shader

#extension GL_EXT_ray_query : require
#extension GL_EXT_buffer_reference : require
#extension GL_EXT_scalar_block_layout : require
#extension GL_EXT_nonuniform_qualifier : require

layout(set = 3, binding = 0) uniform accelerationStructureEXT u_TLAS;

struct HitInfo { bool Hit; bool FrontFace; float T; int Instance; int Geometry; int Primitive; vec2 Bary; mat4x3 ObjectToWorld; };

HitInfo TraceRay(vec3 origin, vec3 dir, float tMax, uint mask)
{
    rayQueryEXT rq;
    rayQueryInitializeEXT(rq, u_TLAS, gl_RayFlagsOpaqueEXT, mask, origin, 0.001, dir, tMax);
    while (rayQueryProceedEXT(rq)) {}                 // opaque only: no candidates to accept
    HitInfo h; h.Hit = rayQueryGetIntersectionTypeEXT(rq, true) == gl_RayQueryCommittedIntersectionTriangleEXT;
    if (h.Hit)
    {
        h.T         = rayQueryGetIntersectionTEXT(rq, true);
        h.FrontFace = rayQueryGetIntersectionFrontFaceEXT(rq, true);
        h.Instance  = rayQueryGetIntersectionInstanceCustomIndexEXT(rq, true);
        h.Geometry  = rayQueryGetIntersectionGeometryIndexEXT(rq, true);
        h.Primitive = rayQueryGetIntersectionPrimitiveIndexEXT(rq, true);
        h.Bary      = rayQueryGetIntersectionBarycentricsEXT(rq, true);
        h.ObjectToWorld = rayQueryGetIntersectionObjectToWorldEXT(rq, true);
    }
    return h;
}

// Reconstruct the surface: fetch the 3 vertices through buffer references (the struct must match the
// H2M static mesh vertex layout byte for byte), interpolate with (1 - b.x - b.y, b.x, b.y),
// transform the position with ObjectToWorld and the normal with its inverse transpose,
// read the GPUMaterial, sample textures with u_Textures[nonuniformEXT(index)] at a fixed LOD.

HRay-traced effects

Goal: replace the raster parts of GI, AO and reflections with rays, and keep the raster versions as fallbacks.

H.1 Probe rays: the payoff of the ray buffer

A compute shader, one thread per ray and probe slot, replaces the capture and the resample of Phase D. It writes exactly the same ray buffer. The blend, the borders, the relocation, the scheduling and the sampling don't change at all.

void main()   // ProbeTrace.glsl (proposed)
{
    int ray = int(gl_GlobalInvocationID.x), slot = int(gl_GlobalInvocationID.y);
    vec3 origin = ProbePosition(BatchProbe(slot));
    vec3 dir = ProbeRayDirection(ray);
    HitInfo h = TraceRay(origin, dir, 1e4, MASK_OPAQUE);
    vec4 result;
    if (!h.Hit)            result = vec4(EnvironmentRadiance(dir), 1e4);
    else if (!h.FrontFace) result = vec4(0.0, 0.0, 0.0, -0.2 * h.T);
    else
    {
        SurfacePoint s = ReconstructSurface(h);
        result = vec4(ShadeSurfaceDiffuse(s, -dir, true), h.T);   // the same function as the capture shader
    }
    imageStore(u_RayBuffer, ivec2(ray, slot), result);
}

Two improvements become possible at the hit: shadow rays towards the sun and the local lights instead of shadow-map lookups (no cascade coverage problem, see B.2), and full textures through the bindless array. With no draw calls involved, the budget can grow from a few probes to hundreds per frame.

H.2 RTAO

From each G-buffer pixel, trace one short ray (length = the AO radius) in a cosine-weighted random direction around the normal, stopping at the first hit (gl_RayFlagsTerminateOnFirstHitEXT). The result is 0 or 1 per pixel; the Phase F temporal filter and spatial denoiser turn it into a smooth AO image. It writes into the same AO image (set 0, binding 15) as GTAO, so nothing else changes. Unlike GTAO, it sees geometry behind other geometry and off screen.

H.3 Ray-traced reflections

  1. From each G-buffer pixel with roughness below a threshold (e.g. 0.5), sample a reflection direction from the GGX distribution of its roughness.
  2. Trace it. On a hit, shade with ShadeSurfaceDiffuse plus a simple specular term (the hit's own reflections come from the environment and the probes). On a miss, use u_EnvRadianceTex.
  3. Denoise with the temporal filter (reflections reproject best along the reflected ray rather than with the surface motion) and a roughness-aware spatial blur.
  4. Bind the result in set 0 (proposed binding 16) and read it in IndirectSpecular(). Above the roughness threshold, keep the environment lookup normalized by the probes (E.4).

This fixes the last big GI problem of the raster version: interiors reflecting the outdoor sky. It also enables glass behind glass and glass in the water reflection (both current limits of the glass material), by tracing refraction rays with the glass mask.

H.4 A path tracer as a reference view

A path tracer follows each pixel's light path through many bounces and accumulates samples over frames while the camera stands still. It is too slow for the editor's normal view, but it is the ground truth: switch to it, let it converge, and compare it with the probes, GTAO and the reflections. With ray queries it can be a single compute "megakernel" reusing TraceRay, ReconstructSurface and the material buffer. The dedicated ray tracing pipeline is an option for performance later.

H.5 What stays raster

Primary visibility (what the camera sees), the main lighting pass, shadow maps for the camera view (shadow rays there are optional), water, bloom, overlays and the composite all stay as they are. That is what makes the renderer hybrid: rays are used only where they do better.

  • H: ray-traced probes converge to the same image as the raster capture (within noise); the path tracer is the final judge.
  • Every new pass gets a profiler scope with a description, so the Rendering Stats panel shows its GPU time.
  • Every new setting is saved in RenderSettings of the .mscene file or in the ProbeVolumeComponent.

14. Glossary and references

Albedothe fraction of light a surface reflects diffusely, per color channel
BLAS / TLASbottom- / top-level acceleration structure: bounding-volume trees over the triangles of a mesh / over all instances of the scene
Chebyshev testan upper bound on the probability that a point is visible, computed from the mean and variance of stored distances (as in variance shadow maps)
DDGIDynamic Diffuse Global Illumination: a probe grid with irradiance and distance moments, updated by rays
G-bufferper-pixel surface attributes (depth, normal, roughness, motion) written before lighting
GTAOGround Truth Ambient Occlusion: horizon-based screen-space AO with analytic cosine-weighted integration
Hysteresisthe fraction of the old value kept in each update; trades stability for responsiveness
Irradiancetotal incoming light at a point, cosine-weighted over the hemisphere around a normal
Octahedral mappinga mapping of the sphere onto a square through an octahedron, with low distortion and simple math
Ray querytracing a ray from any shader stage (here: compute) without a ray tracing pipeline
Refitupdating an acceleration structure's boxes for moved vertices without rebuilding its tree
Spherical Fibonaccia deterministic, evenly spread set of points on a sphere, used for probe ray directions
